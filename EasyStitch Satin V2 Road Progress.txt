## 2026-05-24 09:45:00 IST - Phase B.3 — Manual split boundary preservation

### Current objective
Implement Phase B.3: detect manual split boundaries where both children remain Satin, and insert forced nodes in the road graph at those boundaries.

### Problem
If a user manually splits a Satin path and both children remain Satin, the raster mask merges them into one black region. AutoTrace sees one continuous centreline. The split boundary is lost and road segments ignore the manual split.

### Solution
Two-stage post-processing pipeline added after centerline graph creation:

1. **`_render_object_label_map()`** — Renders each Satin object with a unique grayscale fill (1, 2, 3...) into a label map image at mask resolution. Two adjacent Satin rectangles produce different pixel values (1 and 2) even though the compositing mask merges them as black.

2. **`split_polylines_at_object_boundaries()`** — For each cleaned centreline polyline, walks every point and samples the label map. Where consecutive points belong to different Satin objects, inserts a split at the midpoint. Each resulting polyline carries a `source_object_ids` list.

3. **Wire into `/api/roads/centerline` pipeline** — Split step inserted between `clean_centerline_polylines` and `build_centerline_graph`.

4. **`tag_split_boundary_nodes()`** — Post-processes the graph: walks all nodes and tags any node that connects edges with different `source_object_ids` as `type: "manual_split_boundary"`. Called after `build_centerline_graph`.

5. **Overlay SVG** — `manual_split_boundary` nodes render as magenta (#ff00ff) circles with radius 3.6, distinct from junction (orange), endpoint (green), and pass-through (yellow) nodes.

6. **`build_centerline_graph` updated** — Now carries `source_object_ids` from polylines through to graph edges.

## 2026-05-25 09:18:46 IST - Phase C.9a edge/edge intersection + angle-based T-junction detection

### Current objective
Fix two lingering topology issues in the backend: (1) edges that cross without a backend graph node at the intersection now get a generated node, (2) endpoint-to-edge snapping now uses geometric angle detection instead of a hard offset threshold, so genuine T-junctions snap correctly even at moderate distances while nearby parallel paths are still rejected.

### Changes
- **Edge/edge intersection detection**: `_add_edge_intersection_nodes()` checks every pair of edges for segment-level crossings. Where two polylines geometrically cross without an existing node within snap_tolerance, a `generated_junction` node is created. The downstream edge-splitting loop then splits both edges at this new node, exactly like the old C.8 frontend patch but now in the backend.

If the angle between them exceeds 30°, the connection is treated as a genuine T-junction and allowed at the full snap tolerance. If the angle is ≤30° (near-parallel paths), it falls through to the strict 2px tolerance. This replaces the previous blanket strict_tolerance cutoff for all endpoint nodes from different objects.
