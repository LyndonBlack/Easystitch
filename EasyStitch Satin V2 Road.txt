EasyStitch Satin V2 Road-Graph Centerline Implementation Checklist
0. Scope and non-goals
Goal

Implement a Satin V2 road-graph preparation pipeline that uses:

Pane 3 final Satin-only paths
→ high-resolution black/white raster mask
→ AutoTrace centerline
→ parsed road graph overlay/debug output

This is not yet the final Satin V2 stitch generator. The first goal is to produce a clean, useful road graph from the paths that the user has already assigned as Satin.

Non-goals for this phase

Do not rewrite legacy satin stitching.

Do not change DST/JEF/VP3 export.

Do not change Fill stitching.

Do not run AutoTrace on the original uploaded image.

Do not run AutoTrace on all black paths.

Do not run medial-axis skeletonization on the full filled polygon.

Do not stitch the AutoTrace centerline directly.

Do not invent auto-priority or auto-junction logic yet.

Do not remove the existing manual split / Fill / Satin / Skip workflow.

1. Required pipeline ordering

The order must be:

Pane 1: image prep
Pane 2: trace
Pane 3 Part A: path assignment and manual splitting
Pane 3 Part B: Satin-only raster mask generation
Pane 3 Part C: AutoTrace centerline
Pane 3 Part D: parsed road graph debug overlay
Pane 4: unchanged for now

The centreline/road-graph process must use the current Pane 3 state after user edits, including:

manual splits
new child paths
Fill / Satin / Skip assignments
hidden/skipped paths
current transformed path geometry

Only paths that are currently assigned:

Satin

are included in the raster mask.

Everything assigned:

Fill
Skip
Background
Unset

must be excluded.

Function 1: collect satin objects
def collect_satin_objects(objects: list, assignments: dict) -> list:
    """
    Return only objects currently assigned as Satin.
    Must use the current Pane 3 object list after manual splits.
    """

Rules:

Include only assignment == satin
Exclude fill
Exclude skip
Exclude unset
Preserve object id, d path, color, tx, ty
Function 2: render satin mask
def render_satin_mask(
    objects: list,
    assignments: dict,
    svg_w: float,
    svg_h: float,
    scale: int = 4,
    antialias: bool = False
) -> dict:
    """
    Render only Satin-assigned SVG paths to a binary black/white PNG mask.
    """

Output dict:

{
    "image": PIL.Image,
    "width_px": int,
    "height_px": int,
    "scale": float,
    "satin_object_ids": list[str],
    "excluded_object_ids": list[str],
}

Rules:

White background
Black filled satin paths
No grey antialiasing if possible
Use current object tx/ty transforms
Use SVG viewBox dimensions
Output must map back to SVG coordinates by dividing by scale

Implementation options:

Preferred simple route:

Use cairosvg if available

Alternative route:

Use svgpathtools / shapely polygon rasterization if already available

Do not spend too long inventing a renderer. If path rasterization is difficult, create a temporary SVG containing only satin paths and render that SVG to PNG using a known renderer.

Function 3: clean binary mask
def clean_binary_mask(image, median_filter=True, threshold=128):
    """
    Convert mask to pure 1-bit or L-mode black/white.
    Optional 3x3 median filter.
    """

Rules:

black = satin
white = background
no grey pixels in final mask
Function 4: run AutoTrace
def run_autotrace_centerline(
    mask_image,
    autotrace_path: str = "autotrace",
    despeckle_level: int = 8,
    filter_iterations: int = 4,
    error_threshold: float = 2.0
) -> str:
    """
    Save mask to temp PNG, run AutoTrace --centerline, return SVG text.
    """

Suggested command:

autotrace \
  --centerline \
  --background-color FFFFFF \
  --output-format svg \
  --despeckle-level 8 \
  --filter-iterations 4 \
  --error-threshold 2.0 \
  --output-file temp_centerline.svg \
  temp_mask.png

If any option fails because this AutoTrace build does not support it, fall back to a minimal command:

autotrace \
  --centerline \
  --background-color FFFFFF \
  --output-format svg \
  --output-file temp_centerline.svg \
  temp_mask.png

The function must return a clear error if AutoTrace is missing:

AutoTrace not found. Install autotrace and ensure it is on PATH.
Function 5: parse AutoTrace SVG paths
def parse_centerline_svg_to_polylines(svg_text: str, scale: float) -> list:
    """
    Parse SVG path/polygon/polyline/line elements into polylines in original SVG coordinates.
    Divide raster coordinates by scale.
    """

Initial acceptable support:

path d=""
polyline points=""
line x1/y1/x2/y2

If paths contain curves, flatten them to polylines using existing SVG path tooling if available.

Output:

[
    {
        "id": "cline_1",
        "points": [[x, y], [x, y], ...],
        "length": 123.4
    }
]
Function 6: clean polylines
def clean_centerline_polylines(
    polylines: list,
    min_length_px: float = 5.0,
    simplify_tolerance: float = 1.0
) -> list:
    """
    Remove tiny paths and simplify jitter.
    """

Rules:

Remove lines shorter than min_length_px
Simplify with Douglas-Peucker if available
Do not remove endpoints
Do not remove obvious junction paths yet
Function 7: build simple graph
def build_centerline_graph(
    polylines: list,
    snap_distance: float = 3.0
) -> dict:
    """
    Snap nearby endpoints, split/represent paths as graph edges.
    Initial version can be endpoint-based only.
    """

Initial graph rules:

Endpoints within snap_distance become same node
Node degree = number of connected edges
degree 1 = endpoint
degree 2 = pass-through
degree >= 3 = junction

Do not implement auto priority yet.

Function 8: build debug overlay SVG
def build_road_graph_overlay_svg(
    svg_w: float,
    svg_h: float,
    satin_objects: list,
    graph: dict
) -> str:
    """
    Display original satin shapes faintly, centreline edges, and graph nodes.
    """

Overlay colors:

satin path fill: black, opacity 0.15
centreline edge: cyan or yellow
endpoint node: small green circle
junction node: red/orange circle

This phase is successful when:

1. Manual splits in Pane 3 are reflected in the Satin-only mask.

3. AutoTrace runs on the mask, not the original image.
4. The returned centreline overlay visually follows the selected Satin paths.
5. The overlay has recognizable puppy outline/ear/head road graph.

12. Guardrails

If the centreline is bad, check in this order:

1. Is the Satin-only mask correct?
2. Are Fill/Skip paths accidentally included?
3. Are manual split children represented correctly?
4. Is the mask pure black/white?
5. Is scale high enough?
6. Are AutoTrace options too aggressive?
7. Is graph cleanup pruning too much or too little?

Do not immediately change Satin V2 or stitch generation.

If the mask is wrong, fix Pane 3 object/assignment collection.

If the mask is right but AutoTrace is wrong, tune AutoTrace and cleanup.

If AutoTrace is right but graph is wrong, fix SVG parsing/snap/graph building.

on the final Satin-only geometry.

Do not solve more than that in this phase.

Phase B.3 — Manual split boundary preservation

Problem:
The visible Satin mask correctly respects Fill/Skip reassignment, but if a manually split parent creates two adjacent child paths and both remain Satin, the raster mask merges them into one black region. AutoTrace sees one continuous centreline and the manual split boundary is lost.

Goal:
Manual split boundaries from Pane 3 must become forced road-graph nodes when both split children remain Satin.

Inputs:
- current Pane 3 structureObjects
- stitchAssignments
- AutoTrace centreline graph
- current Satin object geometries

Rules:
1. Continue using the visible Satin compositing mask for AutoTrace.
2. Do not change the mask behaviour.
3. After graph creation, compare graph edges against Satin object boundaries.
4. If a centreline edge crosses a boundary between two different current Satin objects, insert a forced node.
5. Split that edge at the forced node.
6. Mark the new node type as manual_split_boundary.
7. Preserve this node in roadSegments and exported Road JSON.
8. Do not stitch yet.

Acceptance:
- If a user manually splits a Satin object into two Satin children, Build Centerline Graph should show a road segment break at the split.
- If one child is reassigned Fill, current mask knockout behaviour still works.
- Puppy/HappySun/House centrelines remain correct.
- No artificial gaps are introduced into the mask.

Phase C.2 — SVG coordinate system and 0,0 bug prevention

This is critical.

Required SVG rendering rules

The overlay SVG must use the same coordinate system as the original traced SVG:

Every overlay layer must share this same viewBox.

Layers:

Layer 1: faint original/current Satin visible mask or current path outlines
Layer 2: centerline edges
Layer 3: graph nodes
Layer 4: selected/hover highlight
Layer 5: optional labels
Do not do this

Do not place faint outlines as separate absolutely positioned SVGs without matching viewBox.

Do not use CSS left/top positioning for individual paths.

Do not create a new SVG with default viewBox="0 0 100 100".

Do not render path overlays in screen coordinates while centerlines are in SVG coordinates.

Correct pattern
<div id="road-editor-viewport">
  <svg id="road-editor-svg"
       viewBox="0 0 ${svg_w} ${svg_h}"
       preserveAspectRatio="xMidYMid meet">
    <g id="road-bg-layer"></g>
    <g id="road-edge-layer"></g>
    <g id="road-node-layer"></g>
    <g id="road-highlight-layer"></g>
  </svg>
</div>

Phase E.1 — Backend helper

Create:

easystitch_core/satin_v2.py

Initial functions:

def generate_segment_rungs(segment, visible_satin_mask_or_polygons, spacing_px):
    ...

or if easier:

def generate_segment_rungs_from_mask(segment_points, mask_image, scale, spacing_px):
    ...
Algorithm

For each segment:

1. Walk along centreline points.
2. Resample at satin spacing distance.
3. For each sample:
   - compute tangent from neighbouring points
   - compute normal
   - cast ray/line across visible Satin mask or polygon
   - find black-to-white boundary crossings
   - use outermost crossings as rung p1/p2
4. Return list of rungs.
Important

Use the visible Satin mask, not original raw satin object only, for the first implementation. This already solved the house nested-fill problem.
